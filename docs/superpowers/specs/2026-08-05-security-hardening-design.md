# Eval Bar AI 兼容式安全加固设计

- 状态：方案已确认，待实施。
- 日期：2026-08-05。
- 方案：兼容式安全加固，不迁移或改写现有用户数据。

## 背景与目标

生产站点已经通过 `https://evalbar.cn` 和 `https://www.evalbar.cn` 提供 TLS，但 Node 服务的 `3000` 端口仍可从公网通过明文 HTTP 访问，形成 HTTPS 绕过入口。代码审计和隔离复现同时发现：密码使用无盐 SHA-256、Token 无过期且明文存储、浏览器把 Token 保存到 `localStorage`、首用户自动成为管理员、登录与 AI 接口没有限流、反馈缺少 Schema 校验、招聘模式存在间接 Prompt Injection 风险，以及安全响应头、CORS、上传资源限制和前端第三方脚本管理不足。

本次目标是按风险顺序关闭这些攻击路径，同时保持现有用户、管理员权限、报告、反馈、附件和 Prompt 内容不变。允许部署后让现有登录会话失效并要求用户重新登录，但不删除或更新数据库中的旧 Token 记录。

## 数据保护边界

本次实施必须遵守以下约束：

- 不修改数据库 Schema，不执行数据迁移。
- 不更新或删除现有 `users`、`tokens`、`reports`、`feedback`、`report_attachments`、`system_prompt` 或 `candidate_system_prompt` 记录。
- 不读取或输出真实密码哈希、Token、候选人材料、报告正文和附件正文。
- 不改变现有用户的 `is_admin` 状态。
- 不自动重写现有 SHA-256 密码哈希。
- 不物理删除旧 Token；部署后的认证只接受新摘要格式，使旧明文 Token 立即失效。
- 新注册、新登录、新反馈和新报告产生的新记录属于正常产品行为，不是对既有数据的迁移；自动化验证只使用隔离数据库和合成数据。
- 生产防火墙、Nginx、PM2、环境变量和部署操作必须在本地验证完成后单独取得授权。

## 方案选择

### 采用：兼容式安全加固

在现有表结构内区分新旧密码格式：新密码使用带算法标识的 scrypt 编码，旧 SHA-256 密码继续兼容验证。新 Token 只把摘要写入现有 `tokens.token` 字段；认证只查询摘要格式，不再接受旧明文 Token。旧密码不自动升级，旧 Token 不删除，但部署后立即失去认证能力。

这样可以在不迁移既有数据的前提下保护所有新凭据，并通过凭据格式切换强制重新登录。代价是数据库中仍会保留不可用的历史 Token 和旧密码哈希；它们的物理清理与密码升级需要未来单独授权。

### 不采用：完整凭据迁移

直接改表、批量替换密码哈希、清理 Token、增加持久化额度表可以获得更干净的最终状态，但会修改现有数据，不符合本次约束。

### 不采用：仅外围加固

只关闭公网端口并增加 Nginx 安全头无法解决永久 Token、弱密码、首用户管理员、公开注册滥用、反馈拒绝服务和 Prompt Injection，不能视为完整修复。

## 总体实施顺序

| 阶段 | 主要工作 | 完成标准 | 数据影响 |
|---|---|---|---|
| 1 | 关闭明文应用入口 | Node 默认只监听回环地址；生产文档只使用 HTTPS 域名 | 无 |
| 2 | 认证与会话加固 | Cookie 会话、Token 到期、新密码 scrypt、取消首用户管理员 | 不改既有记录 |
| 3 | 限流与资源保护 | 注册、登录、反馈、分析限速；上传和 AI 并发受控 | 无新增业务表 |
| 4 | 输入与输出安全 | 反馈 Schema、Prompt 边界、Markdown 外链限制 | 不清理旧反馈 |
| 5 | 浏览器与 HTTP 加固 | 同源 API、安全响应头、本地前端依赖、API JSON 404 | 无 |
| 6 | 对抗复测与发布准备 | 自动化、构建、隔离攻击回归和生产操作清单 | 仅合成数据 |

## 阶段 1：关闭明文应用入口

Node 服务新增明确的监听主机配置：默认 `HOST=127.0.0.1`，`app.listen(PORT, HOST)`。同机 Nginx 继续通过 `127.0.0.1:3000` 访问后端；只有 Docker 等明确需要容器端口映射的环境才显式传入 `HOST=0.0.0.0`。

仓库中的生产 URL 单一来源统一为 `https://evalbar.cn`。服务器本机健康检查继续使用 `http://127.0.0.1:3000`，外部冒烟只使用 HTTPS 域名。部署文档必须明确：公网 `3000` 应拒绝连接，不能把应用监听地址当作公开入口。

生产侧最终仍需关闭云安全组或主机防火墙的 `3000/tcp`。代码绑定和网络访问控制是两层独立防线，任一层都不能省略。

## 阶段 2：认证与会话加固

### Cookie 会话

登录和注册成功后，服务端设置名为 `evalbar_session` 的 Cookie：

- `HttpOnly`，禁止前端 JavaScript 读取。
- 生产环境启用 `Secure`。
- `SameSite=Strict`。
- `Path=/`。
- `Max-Age` 与服务端绝对有效期一致。

认证中间件优先读取 Cookie。为兼容非浏览器 API，可继续接受 `Authorization: Bearer`，但只接受部署后签发、能匹配摘要记录且未到期的新 Token；浏览器前端不再保存或发送 Bearer Token。所有前端请求使用同源 Cookie，退出登录由服务端清除 Cookie。

前端启动时删除旧的 `auth_token` 和 `admin` 本地键，不复用其中的 Token；通过 `/api/auth/me` 恢复用户身份。登录角色 `evalbar_auth_mode` 继续作为产品路由状态保留，但不作为权限凭据。部署后现有用户需要重新登录。

### Token 存储与有效期

新登录生成随机原始 Token，只把 `sha256:<hex>` 摘要存入现有 `tokens.token` 字段，原始 Token 只进入 HttpOnly Cookie。验证时只查询摘要格式，不回退查询旧明文 Token。所有新 Token 根据 `created_at` 执行绝对有效期校验，时间无效、缺失或超过有效期时统一返回 `401`。

本次不删除旧 Token，也不更新其字段。旧 Token 即使仍存在于数据库，也会因为格式不再受信任而立即失去认证能力。登出只删除当前新会话对应的摘要记录；这是用户主动触发的正常会话行为。

### 密码存储与规则

新注册密码至少 10 个字符，服务端和前端使用同一规则。新密码使用 Node 内置 `crypto.scrypt`、随机盐和常量时间比较，编码格式包含版本、参数、盐和摘要。现有 64 位 SHA-256 哈希继续验证，使原账号仍可登录；登录成功后不自动重写旧哈希。

未来如允许修改用户数据，再采用显式迁移或用户主动修改密码的方式消除遗留 SHA-256 哈希。本次不得把“新密码安全”描述成“所有历史密码已迁移”。

### 管理员初始化

公开注册永远创建普通用户，不再根据用户数量自动设置管理员。现有管理员状态保持不变。

新增独立的一次性管理员初始化脚本，仅允许在本机显式运行，并要求目标用户名、密码通过命令参数或交互输入提供。脚本发现已有用户或管理员时必须失败关闭，不能隐式提升普通用户。本次只实现和测试脚本，不在生产执行。

## 阶段 3：限流、AI 配额与上传资源保护

限流按用途分开，避免一个接口耗尽全站额度：

- 注册：按 IP 的低频窗口限制。
- 登录：同时按 IP 和规范化用户名限制，成功登录后只清理对应用户名计数。
- 反馈：按用户限制短时间写入次数。
- AI 分析：按 IP 和用户双重限制，并限制单用户并发。

当前生产是单 PM2 进程，因此第一版使用进程内限流和并发计数，不修改数据库。服务重启会重置计数，文档必须明确这一边界；未来多实例部署前需要更换为 Redis 或其他共享存储。

AI 分析还应限制逐字稿、岗位、能力模型、JD 和解析后简历文本的字符数，并为单用户设置每日进程内调用额度。超过限制统一返回 `429` 或 `413`，不得调用 AI 提供商。供应商控制台预算上限属于生产配置，发布阶段单独处理。

Multer 增加 `fields`、`parts`、`fieldSize` 等限制，Nginx 最终设置对应 `client_max_body_size`。上传失败只返回稳定错误码，不回显底层解析异常。

## 阶段 4：输入、模型与渲染安全

### 反馈 Schema

服务端要求：

- `reportId` 为非空字符串，并继续执行报告所有权校验。
- `rating` 为 1 到 5 的整数。
- `comments` 为可选字符串，具有固定长度上限。
- `specificIssues` 为可选字符串数组，限制项目数、单项长度并使用允许值集合。

读取历史反馈时执行兼容归一化：非数组 `specificIssues` 作为空数组返回，非法评分只用于管理展示兜底，不修改数据库原值。管理页面继续使用 `Array.isArray()` 防止历史异常数据触发 `.map()` 崩溃。

### Prompt Injection

Candidate 与 Recruiter Prompt 都必须声明简历、职位描述和面试记录为不可信数据，只能作为证据，不能改变系统规则、输出格式或权限。现有 JSON 包装继续保留，并在模型输出后验证必需章节和允许格式。

本次不尝试通过关键字黑名单“清洗”自然语言，因为攻击指令可以变形。防线由系统指令隔离、结构化数据边界、输出验证、渲染限制和对抗样本共同组成。

### Markdown 渲染

报告 Markdown 禁止渲染远程图片和原始 HTML。链接只允许 `http:`、`https:` 和 `mailto:`，使用安全的 `target` 与 `rel`；不符合协议的链接按纯文本处理。模型输出不能触发浏览器向任意图片地址发送请求。

## 阶段 5：浏览器和 HTTP 加固

应用 API 全部同源访问，不再使用宽松 `cors()`。不支持第三方站点携带 Cookie 调用 API。对所有非 GET/HEAD 请求校验 `Origin`；生产只接受规范域名，开发环境接受本机 Vite 地址。

Express 增加安全响应头：CSP、HSTS、`frame-ancestors`、`X-Content-Type-Options`、Referrer Policy 和合理的 Permissions Policy，并关闭 `X-Powered-By`。生产 Nginx 在发布阶段配置同等或更严格的头部，避免只依赖应用层。

移除运行时 Tailwind CDN 和无用 import map。Tailwind 改为构建期生成，Inter 字体改为本地依赖或可靠的系统字体回退，确保生产页面不执行第三方 CDN JavaScript。CSP 以自托管脚本和样式为默认，不为兼容旧 CDN 放宽到任意来源。

未匹配的 `/api/*` 返回 JSON `404`，不得落入 React SPA 的 `index.html`。认证和注册错误使用稳定、模糊的客户端消息；详细原因只允许出现在不含敏感数据的服务端诊断中。

## 错误处理与兼容行为

- 旧明文 Token 或新 Token 超期：返回统一 `401`，前端清理认证状态并进入登录页。
- Cookie 缺失：不从旧 `localStorage` Token 静默恢复。
- 旧 SHA-256 密码正确：允许登录并签发新 Cookie，不重写密码记录。
- 密码不符合新规则：只阻止新注册，不阻止现有旧密码账号登录。
- 没有管理员的空库：普通注册不会获得管理员；需要运维显式执行初始化脚本。
- 限流触发：返回 `429` 和稳定错误码，不暴露账号是否存在。
- 历史异常反馈：管理页安全显示，不自动修复数据库。
- Prompt 输出不合约：拒绝保存或返回明确的分析失败，不把未经验证的结构当作可信结果。

## 测试策略

所有行为变更遵循测试驱动开发：先写最小失败测试，确认失败原因正确，再实现最小代码并运行全量回归。

自动化测试至少覆盖：

- 默认监听 `127.0.0.1`，显式 `HOST` 可覆盖。
- 生产 URL 文档不再出现公网 HTTP `:3000`。
- Cookie 属性、登录恢复、退出清理和前端不保存 Token。
- 新 Token 摘要存储、旧明文 Token 拒绝、绝对过期和无效时间拒绝。
- scrypt 新密码、旧 SHA-256 登录兼容、新密码长度和常量时间校验。
- 空库首注册不是管理员，初始化脚本失败关闭。
- 注册、登录、反馈、AI 的限流和单用户并发。
- 超限请求不会调用 AI 客户端。
- multipart 字段、parts、字段长度和文件大小限制。
- 反馈 Schema 与历史异常反馈归一化。
- Prompt 不可信数据边界和输出合约。
- Markdown 图片禁用、危险链接拒绝、安全链接属性。
- CORS/Origin、安全响应头、`X-Powered-By` 移除和 API JSON 404。
- 构建产物不加载 Tailwind CDN 或 `esm.sh`。

完成后运行：

```bash
npm test
npm run build
npm audit
```

隔离对抗复测使用临时 SQLite 和合成账号，验证弱密码、永久 Token、首用户管理员、暴力登录、AI 滥用、反馈持久化拒绝服务、Prompt 注入和 Markdown 外链均被阻断。不得对生产执行注册、登录爆破、真实 AI、上传压力或跨用户数据测试。

## 生产发布与验收边界

本地实施不包含生产发布。代码和构建验证完成后，生产变更需要单独授权，范围包括：

- 在本地或 CI 构建 `dist/`，禁止在 1.9 GB、无 swap 的生产主机构建。
- 上传并原子替换构建产物与代码，重启 PM2。
- 检查 Node 只监听 `127.0.0.1:3000`。
- 关闭云安全组和主机防火墙的公网 `3000/tcp`。
- 更新 Nginx 安全响应头、请求体限制和规范域名跳转。
- 设置 AI 提供商预算告警或费用上限。

生产验收必须同时满足：

- `https://evalbar.cn` 首页、登录和受保护 API 正常。
- `http://evalbar.cn` 跳转 HTTPS。
- 外网访问 `evalbar.cn:3000` 和服务器 IP `:3000` 拒绝连接或超时。
- 登录响应只通过安全 Cookie 建立会话，页面存储中不存在 Token。
- 部署前会话无法继续认证，用户可使用原账号密码重新登录。
- 未授权端点、跨用户报告和管理员端点继续正确拒绝。
- 生产数据的表数量、用户数量、报告数量、附件数量和关键文件哈希在部署前后保持一致；验证只比较计数和哈希，不展开敏感内容。

## 明确不包含

- 不迁移或清理现有密码、Token、反馈和报告。
- 不新增数据库字段、索引或额度表。
- 不把登录角色升级为服务端权限属性。
- 不引入 Redis、多实例共享限流或独立认证服务。
- 不执行生产数据修复、生产压力测试或真实 AI 对抗调用。
- 不在本次本地实施中修改 `.env*`、密钥、云安全组、Nginx 或 PM2。
