# 浏览器端文字 PDF 导出设计

- 状态：已实现并部署生产。
- 日期：2026-08-03。
- 视觉方向：A，保留网页的深色章节条、卡片感、品牌色和相对宽松的留白，不要求与网页像素级一致。

## 背景与问题

当前报告页使用 `html2pdf.js`：先由 `html2canvas` 以 `scale: 2` 把整个报告转成位图，再由 `jsPDF` 按 A4 页面切分。即使增加 `pagebreak` CSS 和隐藏导出无关元素，分页仍发生在已经栅格化的长图上，因此浏览器无法理解文字行、段落和标题边界。现有 PDF 中出现的文字横向截断，本质上是图片切页位置穿过文字行，不是报告原文缺失。

本次设计以本地数据库现有报告的统计特征为验证基准。当前最长报告约 3,588 字，包含 6 个一级章节和 7 个详细评估维度，对应面试记录约 19,218 字；正式测试使用匿名等长夹具，不把真实候选人正文写入代码、测试快照或日志。

## 目标

- 从根本上消除文字行被页面边界截断的问题。
- 用户点击“导出 PDF”后直接下载文件，不打开系统打印或存储窗口。
- 正常阅读报告后再点击时，下载使用已准备好的 PDF Blob，点击后的等待时间不高于当前方案。
- PDF 中的文字可搜索、选择和复制。
- 保留视觉样稿 A 的主要特征：品牌紫、深色章节条、浅色卡片、清晰的信息层级和适度留白。
- Candidate 与 Recruiter 报告共用同一导出管线，同时保持各自现有内容结构和产品语义。
- 不增加后端 Chromium、生产 PDF 服务、数据库字段或文件持久化。

## 非目标

- 不追求 PDF 与响应式网页像素级一致。
- 不保留网页交互，例如折叠、悬停、滚动导航和按钮。
- 不把面试逐字稿、简历正文或其他未展示材料额外加入 PDF。
- 不在服务器保存生成结果，不做历史 PDF 缓存或数据库迁移。
- 不在本次迭代中修改报告 Prompt、报告内容或评分逻辑。
- 不执行生产部署；发布仍需单独授权。

## 方案选择

### 采用：浏览器端 `pdfmake` 文字排版 + Web Worker + Blob 缓存

使用 `pdfmake 0.3.11` 构建 A4 文档定义。该引擎直接布局文字、列表、表格、背景和页眉页脚，能够生成 Blob，并支持通过 `pageBreakBefore` 避免章节标题孤立在页尾。生成工作放在独立 Web Worker 中，报告页面首屏完成后启动；主线程只负责准备结构化数据、接收 Blob 和触发浏览器下载。

选择该方案的原因：

- 与现有 Markdown 报告结构匹配，不需要复制网页 DOM 或再次截图。
- 能精确控制标题、段落、卡片、页边距和分页规则。
- `getBlob()` 适合后台预生成与点击复用，不需要系统窗口。
- 不增加生产服务器进程、Chromium 体积或服务端并发压力。

### 不采用：后端 Chromium 打印

后端打印最接近网页，但会增加 Chromium 运行依赖、服务器内存与 CPU 峰值、冷启动时间和维护成本，也无法满足“不增加导出时间”的优先约束。

### 不采用：继续修补 `html2pdf`

现有方案的输入是整页位图，无法稳定识别文字行和段落边界。继续叠加 `break-inside`、缩放或切页偏移只能降低复现概率，不能提供“长报告不截字”的保证。

## 总体架构

导出管线拆成四个职责明确的单元：

1. **报告结构解析器**：把 Markdown 和报告元数据转换成与渲染器无关的 `ReportDocumentModel`。
2. **PDF 文档构建器**：把 `ReportDocumentModel` 转换为 `pdfmake` 的 `TDocumentDefinitions`，只负责内容、样式和分页规则。
3. **PDF Worker**：动态加载 `pdfmake` 和中文字体配置，生成 Blob，并把成功或错误消息返回主线程。
4. **页面侧准备器**：管理预生成时机、当前报告缓存、下载、重试和资源释放。

数据流为：

```text
ReportView 中的报告数据
  -> ReportDocumentModel
  -> Worker 消息
  -> pdfmake 文档定义
  -> PDF Blob
  -> 页面内存缓存
  -> 用户点击后 <a download> 直接下载
```

任何单元都不得依赖候选人真实数据库内容；输入只来自当前已授权并已加载到报告页的数据。

## 模块边界

### `services/reportDocumentModel.ts`

提供纯函数，将现有 `analysis.result`、`analysisMode`、岗位名称、文件名和创建时间转换为统一模型。

模型至少包含：

- 报告标题、模式、生成日期和来源文件名。
- 一级章节及其标题。
- 二级维度、段落、无序列表、有序列表和强调文本。
- Recruiter 的综合评级与各维度评分。
- Candidate 的结论、值得保留的做法、核心问题、示范回答和准备清单。

当前 `ReportView.tsx` 内与 Candidate/Recruiter 结构解析相关的纯逻辑应迁入该模块，网页渲染和 PDF 构建共同消费同一模型，避免两套正则逐渐产生差异。该模块不包含 React、DOM、Blob 或 PDF 依赖。

### `services/pdf/reportPdfDocument.ts`

把统一模型转换为 `pdfmake` 文档定义，集中维护 PDF 视觉 token 和分页策略。页面组件不得直接拼装 `pdfmake` 节点。

视觉规则：

- A4 纵向，页边距约 10–12 mm，给页脚预留固定空间。
- 首页使用深 slate 标题卡和品牌紫辅助信息。
- 一级章节使用深 slate 背景、白色标题；圆角和阴影只做 PDF 引擎可稳定实现的近似，不为像素级还原引入截图。
- 二级维度使用品牌紫标题和浅紫分隔线。
- 正文使用深 slate，保持可读行高；评分和重要标签使用统一加粗层级。
- 内容卡使用白底、浅 slate 边框和适度内边距；不使用重阴影。
- 页脚包含 Eval Bar AI、保密提示和“第 X / Y 页”。
- Candidate 不显示 Recruiter 总分或招聘结论；两种模式继续遵守现有产品语义。

分页规则：

- 文字段落只能在完整文字行之间分页，禁止位图切割。
- 一级章节标题后至少保留一个正文块；二级标题后至少保留一段或一个列表项。
- 短卡片尽量整块放在同一页；高于剩余空间的长卡片允许跨页，不能为了 `keepTogether` 产生接近整页的空白。
- 列表项可以在行边界分页，但项目符号和首行必须同页。
- 不对整个章节使用 `unbreakable`，避免长章节溢出或异常留白。

### `services/pdf/reportPdf.worker.ts`

Worker 接受带 `requestId` 的结构化模型，返回以下互斥消息之一：

- `{ requestId, status: 'success', blob }`
- `{ requestId, status: 'error', code, message }`

Worker 内部动态导入 `pdfmake 0.3.11`，注册项目自托管的简体中文字体，然后调用 `getBlob()`。报告正文、文件名、用户信息或字体下载响应不得写入控制台。

Web Worker 是性能边界，不是可选优化。实施的第一项技术验证必须证明 Vite 生产构建下 Worker 可以加载 `pdfmake`、字体并返回中文 PDF Blob。如果验证失败，应停止并报告兼容性问题，不得静默退回主线程同步生成。

### `services/pdf/reportPdfClient.ts`

页面侧管理器按报告身份和内容摘要缓存一个生成任务与 Blob：

- 报告正文首次稳定显示后，通过 `requestIdleCallback` 启动；不支持该 API 时使用短延迟任务，不阻塞首次 React commit。
- 同一报告只允许一个进行中的生成任务，重复调用复用同一个 Promise。
- 点击时若 Blob 已就绪，立即创建对象 URL 并触发带 `download` 属性的隐藏链接。
- 点击时若仍在生成，等待同一个 Promise，并沿用现有“生成中…”按钮状态；不启动第二次生成。
- 报告内容或报告 ID 变化时取消旧请求并释放旧 Blob。
- 页面卸载后调用 `URL.revokeObjectURL()`，终止 Worker 并释放引用。
- Blob 不写入 `localStorage`、IndexedDB、数据库或服务器。

## 中文字体

使用项目自托管、许可允许再分发的 Noto Sans SC 字体，不从第三方 CDN 运行时加载。字体资产固定放在 `public/fonts/`：`NotoSansSC-Regular-v1.otf`、`NotoSansSC-Bold-v1.otf` 和对应许可证文件。两个版本化字体 URL 由 Worker 注册，后续升级通过递增文件名版本避免旧缓存污染。

字体只由 PDF Worker 懒加载，不进入报告首屏的同步 JavaScript。采用 Noto CJK 官方 `SubsetOTF/SC` 资源，两个字重原始体积合计约 16.9 MB；首次字体传输预算上限为 18 MB。不能通过继续删除字符来压缩体积后无提示显示方框。

字体加载失败时，导出失败并向用户显示可重试提示；不得生成缺字、方框或不可复制的降级文件。

## 页面交互

“导出 PDF”按钮保留当前位置、图标和文件名规则：`EvalBar_Report_YYYY-MM-DD.pdf`。

状态规则：

- 后台准备期间仍显示“导出 PDF”，不打断用户阅读。
- Blob 已准备好时，点击直接下载。
- 用户过早点击且任务仍在执行时，按钮显示“生成中…”，任务完成后自动下载。
- 失败时恢复“导出 PDF”，显示“PDF 生成失败，请重试”；再次点击重新生成。
- 不再提供“尝试打印本页面”的错误提示，因为产品要求是不打开系统窗口。
- Markdown 下载、简历下载、分享和其他工具栏行为保持不变。

需要真实表达性能边界：后台预生成把等待提前到阅读阶段，但不能保证用户打开页面后立刻点击时绝对零等待。验收目标是准备完成后的点击近似立即下载，并且同设备、同报告的总生成耗时不高于当前截图方案。

## 错误处理与安全

- Worker 初始化、字体加载、文档构建和 Blob 返回分别设置可识别错误码，UI 只展示简短中文提示。
- 单次生成设置超时；超时后终止 Worker、释放中间引用并允许重试。
- Worker 只接收当前页面已经获得授权的报告模型，不自行调用报告 API。
- 不把报告文本、候选人姓名、公司、岗位描述或错误输入写入日志和遥测。
- 字体必须同源自托管，并保留许可文件；不允许运行时访问第三方字体服务。
- 移除 `index.html` 中 `html2pdf.js` CDN 后，导出不再依赖第三方脚本供应链。
- 生成结果只存在于当前标签页内存；退出页面后释放，不改变现有报告访问权限。

## 依赖与构建影响

- 新增本地依赖 `pdfmake@0.3.11`，并新增开发依赖 `@types/pdfmake@0.3.3`；锁定精确版本，避免导出行为随小版本漂移。
- 新增一个由 Vite 单独打包的 PDF Worker chunk。
- 新增自托管 Noto Sans SC 字体和许可证。
- 删除 `index.html` 中的 `html2pdf.js 0.10.1` CDN 引用，以及 `ReportView.tsx` 中的全局声明和截图导出配置。
- 不新增全局依赖、系统包、后端进程、环境变量或数据库字段。

生产构建必须确认普通首页和非报告页面不会同步加载 PDF 引擎与字体；这些资源只能在报告页后台任务启动后请求。

## 性能预算

以匿名等长夹具和同一台测试设备比较当前实现与新实现，至少各执行 5 次，分别记录冷缓存和热缓存：

- 报告首屏渲染不等待 PDF 引擎或字体。
- Worker 运行期间主线程不得出现由 PDF 生成导致的长任务。
- 热缓存下，后台 PDF 生成耗时中位数不得高于当前 `html2pdf` 点击到文件生成的中位数。
- Blob 已就绪后，点击到浏览器接收到下载触发应小于 100 ms。
- 当前最长规模报告的额外峰值内存目标不超过 80 MB。
- 两个字体字重的首次网络传输总量不得超过 18 MB；PDF Worker JavaScript 单独记录 gzip 体积并与首页入口 chunk 隔离。

性能测试结果写入实施记录，不能只凭主观感受宣称“更快”。

## 测试与验收

### 自动化测试

- 结构解析器覆盖 Recruiter 与 Candidate、新旧报告格式、空章节和超长段落。
- PDF 文档构建器覆盖 6 个一级章节、7 个维度、列表、强调、评分、Candidate 示范回答和准备清单。
- 分页规则测试保证章节标题不会成为页面最后一个节点。
- 客户端缓存测试覆盖预生成、重复点击复用、内容变化失效、失败重试、超时和卸载释放。
- Worker 协议测试覆盖成功 Blob、字体失败和构建失败，且错误消息不包含报告正文。
- 静态测试禁止重新出现 `html2pdf`、`html2canvas` 或系统打印回退。
- 构建产物测试确认 PDF 引擎和字体不进入首页入口 chunk。

### PDF 内容验证

使用匿名等长夹具生成最终 PDF，并通过 `pdfjs-dist` 提取文字：

- 关键标题、首段、末段和每个维度标记全部存在。
- 提取文本按归一化空白后与输入模型一致，不允许缺段或重复段。
- PDF 页数在合理范围内，不把每张卡片强制独占一页。
- PDF 文字可选择、复制，不是整页图片。

### 视觉验证

按 PDF Skill 流程把每一页渲染为 PNG 并逐页检查：

- 无文字截断、重叠、方框、乱码或超出页边界。
- 标题不孤立在页底，页眉页脚不覆盖正文。
- 长卡片跨页时阅读顺序连续。
- 深色章节条、品牌紫、卡片层级和留白符合已确认的 A 版方向。

至少覆盖：数据库最长报告的匿名等长夹具、一个 Candidate 报告、一个包含超长单段和长列表项的边界夹具。

### 项目验证

代码完成后运行：

```bash
npm test
npm run build
```

涉及真实数据库报告的人工验收只读取当前账号有权访问的报告，不打印正文、不生成快照、不提交产物。生产部署前重新执行浏览器下载、PDF 逐页渲染和线上静态资源加载检查。

## 发布与回滚

本设计不包含部署。获得生产发布授权后，按项目运行手册备份完整 `data/`、安装锁定依赖、运行测试和构建，再重启 PM2。虽然本次没有 schema 变更，仍按标准流程保护 SQLite 与简历附件。

回滚只需恢复上一版本前端构建和依赖锁文件；数据库和报告数据不需要转换。旧的 `html2pdf` 代码在新方案验收通过后从源码移除，不保留隐藏开关，避免两个导出路径长期漂移。

## 验收结论标准

只有同时满足以下条件，才能声明修复完成：

1. 匿名最长报告、Candidate 报告和长段落边界报告逐页渲染均无截字。
2. 文字提取验证无缺失、无重复，且 PDF 内容可搜索复制。
3. 正常阅读后点击直接下载，不打开系统窗口。
4. 热缓存生成速度不慢于当前方案，准备完成后的点击触发小于 100 ms。
5. 首页首屏不加载 PDF 引擎和字体，报告页主线程不被生成任务阻塞。
6. Candidate 与 Recruiter 的内容语义、权限边界和现有其他下载功能没有回归。
