# 录音上传界面重设计方案

## 目标

重设计候选人与招聘方共用的录音导入入口，让用户先选择录音、理解处理方式并主动开始上传。上传完成后的转写、说话人确认、逐字稿修订和分析链路保持不变。

## 视觉目标

- 参考图：`docs/superpowers/specs/assets/recording-upload-reference.png`
- 保持现有浅色界面、slate 中性色和 indigo 到 violet 的品牌渐变。
- 初始状态以虚线拖拽区作为主要操作，展示格式、500 MB 和 60 分钟限制。
- 选择文件后展示文件卡片、处理说明、授权勾选框和“上传并转写”主按钮。
- 使用 `lucide-react` 图标和现有 `Button`、`Card` 视觉基元，不引入图片资源或新的强调色。

## 交互流程

1. 用户拖拽录音或点击“选择录音”。选择文件时只做浏览器端校验，不立即上传。
2. 文件校验通过后显示文件名和大小，用户可以更换文件。
3. 用户确认有权使用材料并同意处理方式后，“上传并转写”按钮可用。
4. 点击按钮后沿用现有分块上传和后台转写任务。
5. 上传中显示真实上传百分比；后台转写中明确提示可以稍后回来。
6. 转写完成后沿用现有试听、说话人角色确认和逐字稿编辑能力。
7. 最终按钮文案改为“确认并填入面试记录”，明确该操作不会立即开始 AI 分析。

## 状态和错误处理

- 初始化、服务未配置、恢复任务、上传、排队、转写、失败、逐字稿就绪等现有状态全部保留。
- 拖拽非支持格式、空文件或超限文件时复用现有校验信息。
- 上传失败与任务失败继续使用现有重试或重新选择路径。
- 处理详情默认以紧凑说明呈现，包含第三方转写、24 小时临时音频、30 分钟上传空闲终止和仅分析回答文字。

## 响应式与无障碍

- 桌面端保持紧凑卡片；移动端文件信息、勾选框和按钮纵向排列。
- 拖拽区域可通过键盘聚焦并触发文件选择。
- 复用原生文件输入、复选框和状态语义，补充明确的 `aria-label` 与 `role="status"`。

## 验收边界

- 候选人与招聘方两个入口共用同一实现。
- 不改材料 API、上传分块大小、容量限制、转写服务或数据库。
- 自动化验证覆盖“选文件不上传、授权后主动上传”的状态规则；完整测试与生产构建必须通过。
- 浏览器对照参考图完成桌面和移动端视觉验收，生产上线后核对主资源 hash、PM2 和 HTTP 状态。
